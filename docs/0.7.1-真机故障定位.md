# 0.7.1 真机故障定位

## 截图能证明什么

iOS 16.2、Dopamine/RootHide。抖音、QQ、百度网盘报告 `删除失败（errno 22）`，累计删除 0；这是实际故障，不应解释成正常保留或继续等待即可解决。
“完全退出”检查已经放行，但不能从旧错误文案确定是路径校验还是 `unlinkat` 失败。

抖音未重新检测时显示旧快照 55.25 MB / 0.59 MB；点击后为 157.26 MB / 3.15 MB。
目录检测只读取 APP 文件，更新插件自己的统计文件，不在 APP 缓存目录生成这些数据。
新数字只证明两轮快照间占用不同，不证明点击检测产生了缓存；等待不会让旧快照自动变为实时大小。

## 本版变更与尚未解决项

- 删除失败记录区分枚举路径边界、打开根/父目录/文件、读文件头、最后身份检查、真正 `unlinkat`。每个目录保留最多 8 条失败样本及 errno，主界面展示具体阶段。
- 没有获得设备上实际失败调用的证据前，不取消 no-follow、身份核对、60 秒或数据库保护，也不把相对删除改成宽泛路径删除。**这是精确定位版本，不能宣称设备 errno 22 已根治。**
- 标明目录大小快照时间及刷新方式。
- 新增“检查网络限制”：点击后 5 分钟内打开目标 APP，再返回设置页。采用带随机标识和有效期的 Darwin state 请求/响应，不依赖 APP 能写共享文件。它只用于诊断，不参与清理授权或配置。
- 可以区分未收到响应、libSandy 授权失败、配置读取失败、未开启/未请求限制、容量未生效、容量为 0 但文件回执写失败。无响应不能单独断言未注入，也可能是通知通信失败。
- 未开启 APP 不发送主动诊断请求、不安装网络 Hook；APP 侧仅注册诊断监听，且没有请求时不产生诊断文件。

## 未知目录如何继续判定

1. 先完整深度检测。未完成、读失败或扫描中变化时不能作完整性判断。
2. 数据库、登录态、下载、草稿和共享状态继续保留。JSON/压缩包/媒体类型本身不证明用途。
3. 优先查 APP 或所用缓存 SDK 对该目录的明确约定。也可记录档案，使用 APP 自带的“清理缓存”后重检作对照；这只支持其实际清除部分的判断。
4. 若仍无用途证据，保持未知，并拿具体父目录名称和档案进一步核查。隔离后能打开 APP，不足以证明用户数据没价值。

## 上游依据

- [RootHide 文件共享说明](https://github.com/roothide/Developer/blob/main/entitlements.md)：配置放在 jbroot 的 var 目录。
- [RootHide libSandy server](https://github.com/roothide/libSandy/blob/main/sandyd/main.m)：profile 内文件路径已经通过 `jbroot` 转换，不能再写入带随机根的路径。
- [RootHide libSandy client](https://github.com/roothide/libSandy/blob/main/libSandy.m)：拿到一个扩展 token 就返回成功，不能替代实际配置读取和回执写入核验。

新增 Probe 头文件和本文档无旧版可备份；已有文件按项目规则备份。原生测试覆盖模拟底层 EINVAL 后文件保留/准确记录及实际 Darwin state API；手机的跨沙盒通知、注入和实际删除仍需新回执验证。
